# Complete Gameplay Mechanics Implementation Plan

## Context

Currently the game has shooting mechanics, movement, weapons, and basic entity systems (players, target dummy, simulated bots). However, there's no death/respawn system, health tracking for the local player, or proper game mode structure. The lobby allows infinite respawning while the maze will need structured game modes with rules.

This plan implements ALL the core gameplay mechanics needed for a fully functional FPS game, preparing the architecture for future game modes while keeping lobby and maze behavior distinct.

pub fn take_damage(&mut self, damage: f32, attacker_id: Option<u32>) {
    if self.dev_mode.god_mode || self.is_dead || self.invulnerable_timer > 0.0 {
        return;
    }

    self.hp = (self.hp - damage).max(0.0);

    // Screen shake / damage effect (optional)

    if self.hp <= 0.0 {

}

When server receives MSG_RESPAWN_REQUEST:
```rust
fn handle_respawn(socket: &UdpSocket, players: &mut HashMap<SocketAddr, Player>,
                  maze: &MazeData, src_addr: SocketAddr) {
    if let Some(player) = players.get_mut(&src_addr) {
        player.health = 100;
        player.is_alive = true;

        let spawn = get_spawn_point(player.world, maze);
        player.position = spawn;

        let mut response = vec![MSG_RESPAWN];
        response.extend_from_slice(&spawn.0.to_be_bytes());
        response.extend_from_slice(&spawn.1.to_be_bytes());
        response.extend_from_slice(&spawn.2.to_be_bytes());

        let _ = socket.send_to(&response, src_addr);
    }
}
```

### 5.4 Match State Update

```rust
fn update_match_state(&mut self, delta: f32) {
    match self.match_state {
        MatchState::Waiting => {
            // Wait for minimum players
            // Server decides when to start
        }
        MatchState::Starting => {
            self.match_countdown -= delta;
            if self.match_countdown <= 0.0 {
                self.match_state = MatchState::InProgress;
            }
        }
        MatchState::InProgress => {
            self.match_timer -= delta;

            // Check win conditions
            if self.match_timer <= 0.0 {
                self.match_state = MatchState::Ended;
            }

            // Check score limit
            if self.game_mode == GameMode::Deathmatch && self.score >= 20 {
                self.match_state = MatchState::Ended;
            }
        }
        MatchState::Ended => {
            // Show scoreboard, wait for next match
        }
    }
}
```

### 5.5 Respawn Behavior by Mode

```rust
fn can_respawn(&self) -> bool {
    match self.game_mode {
        GameMode::Lobby => true, // Always respawn in lobby
        GameMode::Deathmatch | GameMode::TeamDeathmatch => {
            self.match_state == MatchState::InProgress
        }
        GameMode::Elimination => false, // No respawns in elimination
        GameMode::KingOfTheHill | GameMode::CaptureTheFlag => {
            self.match_state == MatchState::InProgress
        }
    }
}

fn get_respawn_delay(&self) -> f32 {
    match self.game_mode {
        GameMode::Lobby => 0.0, // Instant in lobby
        GameMode::Deathmatch => 3.0, // 3 second delay
        GameMode::TeamDeathmatch => 5.0, // 5 second delay
        GameMode::Elimination => 0.0, // N/A
        GameMode::KingOfTheHill => 7.0, // Longer delay
        GameMode::CaptureTheFlag => 5.0,
    }
}
```

## Notes

- Lobby is always in "freeplay" mode - no win conditions, infinite respawns
- Maze uses structured game modes with rules, timers, and score limits
- Dev mode dummy_invincible toggle is redundant (dummy never dies anyway) - remove it
- Simulated bots are perfect for testing death/respawn without needing 2 clients
- Server should be authoritative for all health/damage calculations (prevents cheating)
- Client-side health is just for display - server tracks real values
